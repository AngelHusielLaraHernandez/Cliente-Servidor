\section{Preparación del sniffer}
Primero se revisaron las interfaces de red y se activó el modo promiscuo en \texttt{lo}, ya que el cliente y el servidor se ejecutaron en el mismo equipo. En la terminal con permisos de root se utilizaron los siguientes comandos:
\begin{lstlisting}[style=output]
ip -br link
ip link set lo promisc on
ifconfig lo
gcc sniffer.c -o sniffer
./sniffer
\end{lstlisting}

\captura{snifferpreparacion.png}{Preparación de la interfaz lo y comprobación del modo promiscuo en Linux.}

Lo que vemos aquí es que \texttt{ifconfig lo} muestra la bandera \texttt{PROMISC} y la dirección \texttt{127.0.0.1}. Después se levantó el sniffer en esa misma terminal para esperar el tráfico del puerto 4898.

\section{Prueba con el programa 04}
Para esta primera prueba se utilizó el servidor que envía automáticamente una frase al cliente. Se compiló cada programa por separado y los ejecutables se nombraron \texttt{servidor} y \texttt{cliente}. Con el sniffer activo, se levantó primero el servidor y después se ejecutó el cliente en otra terminal:
\begin{lstlisting}[style=output]
./servidor 4898
./cliente 127.0.0.1 4898
\end{lstlisting}

\captura{programa04.png}{Prueba del programa 04 con las terminales del servidor, cliente y sniffer.}

Lo que vemos en la terminal de la izquierda es que el servidor aceptó al cliente desde \texttt{127.0.0.1} y envió la frase \texttt{El mensaje del servidor es: Conexion exitosa!}. En la terminal de la derecha, el cliente mostró el mismo mensaje y registró 46 bytes recibidos. Después ambos programas terminaron.

Por otra parte, en la terminal del sniffer aparece esa misma frase dentro del payload. El puerto de origen fue 4898 y el de destino 48964, que corresponde al puerto del cliente en esta conexión. Con esto se comprobó que el mensaje enviado por el servidor se podía leer en texto plano.

Además de eso, la dirección MAC aparece con ceros y el paquete se muestra dos veces. Esto corresponde a la captura en loopback; no significa que el servidor haya ejecutado dos veces el envío de la frase.

\section{Prueba con el programa 05}
Ahora bien, para la segunda prueba se utilizó el par de programas 05, donde el cliente y el servidor pueden intercambiar varios mensajes. Se compilaron estos archivos para generar nuevamente \texttt{servidor} y \texttt{cliente}, y se mantuvo el mismo puerto:
\begin{lstlisting}[style=output]
gcc programa05_servidor_internet.c -o servidor
gcc programa05_cliente_internet.c -o cliente
./servidor 4898
./cliente 127.0.0.1 4898
\end{lstlisting}
Los comandos del servidor y del cliente se ejecutaron en terminales distintas. El sniffer permaneció en una tercera terminal con permisos de root.

\captura{programa05.png}{Intercambio de mensajes con el programa 05 y captura del mensaje Hola en el sniffer.}

Para el caso de esta prueba, el cliente inició con \texttt{Hola} y el servidor respondió \texttt{Quien eres?}. Después se envió \texttt{Soy Angel Husiel Lara Hernandez}, a lo que el servidor respondió \texttt{Esta es la Tarea 5?}. El cliente contestó \texttt{Si es la Tarea 5} y recibió \texttt{perfecto}.

Lo que vemos en el sniffer es el mensaje \texttt{Hola} dentro del payload, con IP de origen \texttt{127.0.0.1}, puerto de origen 51008 y puerto de destino 4898. En este caso se capturó un mensaje enviado del cliente hacia el servidor, a diferencia de la prueba anterior.

Por último, el cliente escribió \texttt{adios} y recibió \texttt{respuesta automatica}, con lo que cerró su conexión. El servidor del programa 05 está preparado para regresar a esperar otro cliente después de terminar ese intercambio.
